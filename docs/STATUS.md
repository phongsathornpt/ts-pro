# Implementation Status

## Target architecture correction

The target architecture is **TypeScript 7 for the compiler and Go only for the native runtime/native libraries**. The existing Go compiler under `cmd/` and `internal/` is transitional parity/reference code and must be retired as compile-time stages move into TypeScript 7. The handwritten runtime C implementation has been retired; `runtimego/` now owns the native runtime behind the stable C-compatible LLVM ABI.

## Historical compiler baseline

Commit `6bad298` is the historical native-compiler baseline used before the later dynamic-boundary and concurrency milestones. The current branch has progressed substantially beyond it.

```text
TypeScript 7.0.2
  -> diagnostics + checker/API snapshot
  -> TypeScript 7 AST/checker integration (current Go decoder is transitional)
  -> compiler semantic DTOs
  -> typed HIR + representation/range analysis
  -> MIR / SSA
  -> LLVM IR
  -> native linker + Go runtime ABI
  -> native executable
```

The generated executable does not embed Node.js or V8.

## Runtime migration status

The runtime build now links the cached Go `c-archive` directly. Scheduler/task completion ownership, roots, task groups, context, channels, timers, blocking pool, strings, arrays, objects, JSValue, and heap/GC implementation live in `runtimego/`. Opaque task/group ABI handles are real mmap-backed native pointer tokens; real native state/output/reference fields remain pointer-typed in Go, while `uintptr` is limited to internal scheduler/map keys. `go vet ./...` is clean without `unsafeptr` suppression. Toolchain ABI tests compile against the header generated by `go build -buildmode=c-archive`; deleted `runtime/concurrency/*.c` and handwritten runtime headers are no longer part of the build or test path.

## Remaining sequencing rule

Scheduler/GC lifecycle integration is now in place: task-owned reference state and queued reference-channel values remain explicitly rooted, heap-threshold collection requests are deferred safely across active foreign root stacks, and scheduler return/wait/park/budget paths retry GC at safepoints. Allocator locality is now underway: small native allocations use worker-owned size-class spans with bump-pointer slots, bounded reusable-span caching, zeroed slot reuse, finalizer-safe recycling, page-to-span metadata, and explicit remote-free/span-transfer accounting. Remote frees now use owner-drained allocator inboxes instead of foreign free-list mutation. Heap tracing now uses iterative owner-local mark queues with native-page batching instead of recursive DFS. Larger heaps can use bounded parallel mark-page helpers (hard-capped at 8) that prefer owner-local queues and steal across owners, configurable through `TSNATIVE_GC_MARK_WORKERS`. Already-parked scheduler workers are now claimed first as bounded GC donors, and fallback helper goroutines are created only for remaining assist slots. Root/token/thread-stack/handoff metadata now uses a dedicated mutex, so root lifecycle operations no longer serialize with ordinary heap allocation; collectors still hold `heap -> roots` across mark/sweep to preserve a stable snapshot. Heap/root mutex acquisitions, contention counts, and cumulative wait nanoseconds are now exported through the generated runtime ABI and covered by deterministic contention plus C-header tests. Native stress data then justified a worker-local allocation fast path: active size-class spans allocate without the global heap mutex under a GC world read barrier, live blocks publish through a 64-shard index, and live byte/allocation counters are atomic; span refill/reuse and remote-free processing remain serialized slow paths. In the 8-worker/40k-allocation regression this cuts global heap-lock acquisitions from 40,000 to 24 and cumulative heap-lock wait from roughly 241-279 ms to roughly 0.28-1.34 ms. Root/token state has since been split into 16 independent shards with shard-local root frames, per-thread root stacks, and token pools; token page addresses route cross-worker unregister operations to the correct shard while the GC world barrier preserves collection snapshot semantics. On the same 8-worker/80k-root-operation stress workload, cumulative root-lock wait drops from roughly 224-236 ms to 0-0.115 ms in a five-run sample. The next runtime performance step is measuring the GC world barrier and live-block shard contention before introducing nursery/generational policy.

Every milestone must pass `go test ./...`, `go vet ./...`, native acceptance where applicable, and `git diff --check` before commit.

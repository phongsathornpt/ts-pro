# Implementation Status

## Target architecture correction

The target architecture is **TypeScript 7 for the compiler and Go only for the native runtime/native libraries**. The existing Go compiler under `cmd/` and `internal/` is transitional parity/reference code and must be retired as compile-time stages move into TypeScript 7. The handwritten runtime C implementation has been retired; `runtimego/` now owns the native runtime behind the stable C-compatible LLVM ABI.

## Historical compiler baseline

Commit `6bad298` is the historical native-compiler baseline used before the later dynamic-boundary and concurrency milestones. The current branch has progressed substantially beyond it.

```text
TypeScript 7.0.2
  -> diagnostics + checker/API snapshot
  -> TypeScript 7 AST/checker integration (current Go decoder is transitional)
  -> compiler semantic DTOs
  -> typed HIR + representation/range analysis
  -> MIR / SSA
  -> LLVM IR
  -> native linker + Go runtime ABI
  -> native executable
```

The generated executable does not embed Node.js or V8.

## Current coverage

- functions, recursion, direct calls, closures, escaping function values, classes/inheritance/dispatch, and initial generic specialization;
- arithmetic/comparisons plus proven integer arithmetic fast paths;
- mutable locals, top-level bindings, `if`, `while`, and `for` with SSA phi nodes;
- strings, specialized `number[]`, closed objects, shared heap ownership, and root-aware mark/sweep GC;
- tagged `JSValue` boundaries with primitive dynamic operators and checked unboxing;
- bounded Go scheduler, stackless tasks, work stealing, execution budgets, typed channels, timers, and bounded blocking-call isolation;
- stackless native async/await with typed result transfer, rejection propagation, nested `try`/`catch`/`finally` recovery, immediate `Promise.resolve` / typed `Promise.reject` settlement, task groups, cancellation, and inherited task-local context;
- deterministic Go runtime/object caching, generated `c-archive` ABI headers, native acceptance/differential tests, and performance reports;
- resilient long-lived TypeScript LSP workspaces.

## Runtime migration status

The runtime build now links the cached Go `c-archive` directly. Scheduler/task completion ownership, roots, task groups, context, channels, timers, blocking pool, strings, arrays, objects, JSValue, and heap/GC implementation live in `runtimego/`. Opaque task/group ABI handles are real mmap-backed native pointer tokens; real native state/output/reference fields remain pointer-typed in Go, while `uintptr` is limited to internal scheduler/map keys. `go vet ./...` is clean without `unsafeptr` suppression. Toolchain ABI tests compile against the header generated by `go build -buildmode=c-archive`; deleted `runtime/concurrency/*.c` and handwritten runtime headers are no longer part of the build or test path.

## Remaining sequencing rule

Scheduler/GC lifecycle integration is now in place: task-owned reference state and queued reference-channel values remain explicitly rooted, heap-threshold collection requests are deferred safely across active foreign root stacks, and scheduler return/wait/park/budget paths retry GC at safepoints. Allocator locality is now underway: small native allocations use worker-owned size-class spans with bump-pointer slots, bounded reusable-span caching, zeroed slot reuse, finalizer-safe recycling, page-to-span metadata, and explicit remote-free/span-transfer accounting. Remote frees now use owner-drained allocator inboxes instead of foreign free-list mutation. Heap tracing now uses iterative owner-local mark queues with native-page batching instead of recursive DFS. Larger heaps can use bounded parallel mark-page helpers (hard-capped at 8) that prefer owner-local queues and steal across owners, configurable through `TSNATIVE_GC_MARK_WORKERS`. Already-parked scheduler workers are now claimed first as bounded GC donors, and fallback helper goroutines are created only for remaining assist slots. Root/token/thread-stack/handoff metadata now uses a dedicated mutex, so root lifecycle operations no longer serialize with ordinary heap allocation; collectors still hold `heap -> roots` across mark/sweep to preserve a stable snapshot. Heap/root mutex acquisitions, contention counts, and cumulative wait nanoseconds are now exported through the generated runtime ABI and covered by deterministic contention plus C-header tests. Native stress data then justified a worker-local allocation fast path: active size-class spans allocate without the global heap mutex under a GC world read barrier, live blocks publish through a 128-shard index, and live byte/allocation counters are atomic; span refill/reuse and remote-free processing remain serialized slow paths. In the 8-worker/40k-allocation regression this cuts global heap-lock acquisitions from 40,000 to 24 and cumulative heap-lock wait from roughly 241-279 ms to roughly 0.28-1.34 ms. Root/token state has since been split into 16 independent shards with shard-local root frames, per-thread root stacks, and token pools; token page addresses route cross-worker unregister operations to the correct shard while the GC world barrier preserves collection snapshot semantics. On the same 8-worker/80k-root-operation stress workload, cumulative root-lock wait drops from roughly 224-236 ms to 0-0.115 ms in a five-run sample. World-barrier and live-block contention are now measured directly through the generated ABI. Steady-state allocation/root traffic records zero world-read contention; under 32 concurrent full collections the world barrier dominates synchronization wait, while block-shard wait is comparatively small. A 64/128/256 shard comparison retains 128 shards: median steady-state block-write contention falls from about 308 at 64 shards to 167 at 128 (80 at 256), while empty full-GC fixed cost is about 8.8µs / 13.8µs / 25.1µs respectively and a 1,024-live-object full GC is about 337µs / 242µs / 256µs in the sampled runs. A bounded nursery generation is now implemented: allocations are charged to per-worker nursery buckets (64 KiB default, configurable with `TSNATIVE_GC_NURSERY_BYTES`), safepoints run young-only minor mark/sweep when a bucket fills, survivors promote to old, and the initial automatic major threshold is 1 MiB. Current mutable native-heap reference stores now use compiler/runtime barriers: object `FieldSet`, reference task-continuation spills/Phi stores, channel receive completion slots, and task result/failure completion slots all feed a 64-shard remembered-parent set. Minor GC scans only remembered old parents rather than the full old generation, and a negative raw old-to-young store regression intentionally loses the unremembered young child, proving there is no conservative old-scan safety net left. The generated C ABI exercises the same barrier path and exports barrier-store/remembered-record metrics. In a sampled 1,024-old-block workload with 64 KiB nursery pressure, remembered tracing measures roughly 75-79 µs/minor with no remembered parent and 106-119 µs with one remembered parent, versus 151-168 µs for the earlier conservative old scan and roughly 303-523 µs for a full major. Nursery membership is now tracked in per-owner append-only block lists. Under the GC world write barrier, minor collection drains those lists and resets, traces, promotes, or reclaims only the young candidates; dead young blocks are removed from the 128-shard live-block table by targeted key deletion, while major GC and shutdown clear nursery membership explicitly. Native ABI metrics expose current nursery block count and cumulative minor nursery candidates. In the same 1,024-old-block/64 KiB nursery workload, minor GC now measures roughly 14.4-14.9 µs with no remembered parent and 17.8-18.0 µs with one remembered parent, down from roughly 75-79 µs and 106-119 µs before the membership index. Survival-rate and cadence profiling is now complete for this policy iteration. Major-GC pressure uses explicit old-generation live bytes rather than total live bytes, so aggregate young traffic no longer forces a full collection before per-worker nurseries fill; in the sampled 8-worker/256 KiB workload this changes 0 minors / 15 majors to 8-9 minors / 0 majors. Fixed-byte short-lived throughput is nearly flat across 64-512 KiB nurseries, while sampled 64B-object median minor pause grows from about 0.69 ms at 64 KiB to 1.37 ms / 2.74 ms / 5.48 ms at 128 / 256 / 512 KiB. A 64-cycle survival profile at the 64 KiB default triggers no majors at 0-10% one-minor survival and only 2 / 4 majors at 50% / 100% survival, with modest total-runtime increase, so the runtime retains 64 KiB and promote-after-one-minor rather than adding age-2 remembered-set retention complexity without stronger evidence. Precise heap layout metadata is now active: compiler-generated object shapes, task environments, closure environments, and closure objects carry LLVM-derived reference-offset descriptors; strings and F64 arrays are atomic, and JSValue boxes are either atomic or trace only their reference payload slot. The generic heap/object ABI remains conservative when no descriptor is supplied, preserving compatibility. Trace work is now measured by layout kind through the native ABI. In a sampled full-major benchmark with 1,024 live 2 KiB blocks (2 MiB total), conservative scanning takes roughly 1.60-1.68 ms while atomic layouts take roughly 0.956-1.004 ms; exact regression coverage verifies that precise blocks visit only declared reference slots. MIR escape analysis is now integrated into the build pipeline and performance report. It tracks object/closure allocation provenance through Phi aliases and contained references, then marks escapes through returns/throws, unknown heap stores, calls, tasks, reference channels, JSValue boxing, and suspension boundaries; suspension-bearing functions remain intentionally conservative. A separate stack-placement filter now handles numeric-only object shapes plus proven non-escaping closures in acyclic CFG blocks and rejects unsafe contained/cross-lifetime cases. LLVM lowers numeric objects directly to `alloca`; local closures place both the `{code, env}` cell and capture environment in the parent frame, while captured reference values remain in their original GC shadow-root slots. `examples/stack_object.ts` verifies numeric object placement and `examples/closure_stack_reference.ts` keeps a captured string alive across GC churn before an indirect call. Non-scalarizable reference-bearing objects remain heap-backed until precise stack-root/interior-reference handling is covered, returned/otherwise escaping closures retain precise heap allocation, and scheduler-owned task environments remain heap-backed when their lifetime crosses task ownership. Boxed plain objects and F64 arrays now participate in default JavaScript ToPrimitive fallback: ordinary objects stringify as `[object Object]`, numeric arrays use comma-joined element text, object/array/function numeric coercion no longer aborts, and differential coverage matches the TypeScript-to-JavaScript reference path. Closed object shape identity now survives JSValue boxing without enlarging the box: LLVM passes the semantic shape ID, the runtime stores `shapeID+1` in the existing metadata word, verification rejects invalid object-box shapes, and GC regression coverage proves both metadata and payload remain valid. Dynamic named property reads now build directly on this ABI. The frontend accepts property access through `any`/dynamic unions, MIR carries a `DynamicFieldGet`, and LLVM emits one deterministic helper per property name that switches on boxed shape identity, performs the exact typed GEP/load, boxes the field representation, preserves nested object shape metadata, and returns `undefined` when the receiver/property has no matching closed shape. `examples/dynamic_property_get.ts` matches the TypeScript-to-JavaScript reference path for number/string/boolean/nested-object/missing reads. Dynamic named writes are now implemented on the same closed-shape ABI: LLVM dispatches by boxed shape, checked-unboxes the assigned JSValue into the exact field representation, validates nested object shapes, and routes reference stores through the generational remembered-set barrier. `examples/dynamic_property_set.ts` matches Node and a 1 KiB nursery regression proves a young string assigned through `any` survives after the holder has promoted. Adding brand-new properties remains intentionally unsupported for closed native shapes and fails explicitly. Dynamic callable dispatch remains pending.

Fully scalarizable reference-bearing objects now bypass physical object storage entirely: their field values retain the existing typed SSA shadow roots, pointer-valued scalar Phis remain rooted at materialized reads, and eliminated object allocations no longer add GC roots, allocation safepoints, or object-runtime calls. Immutable stack-local `ObjectNew` sites are now scalar-replaced when they have no aliases or field mutations: LLVM emits neither heap allocation nor `alloca`, initialization stores disappear, and `FieldGet` results reuse the original SSA operands. Mutable numeric local objects are now scalar-replaced too when allocation plus every `FieldSet`/`FieldGet` stay in one basic block: zero-initialized fields and subsequent writes are carried as compile-time SSA state, so the object and field memory traffic disappear entirely. Cross-block mutable objects still use the proven `alloca` fallback. Performance reports distinguish scalar-replaced objects from physical stack objects, and both immutable and mutable native fixtures report one scalar replacement with no heap-object runtime call. Mutable scalar field state now crosses general acyclic CFG regions, not just linear chains and direct diamonds. A deterministic topological worklist computes per-block field state, merge points create synthetic per-field Phi values, and those synthetic Phis can feed later merges without depending on LLVM block emission order. Typed-zero incoming states remain explicit, nested branch-tree LLVM is clang-validated, and `examples/scalar_nested_object.ts` verifies the source-level object is scalar-replaced with no object allocation at runtime. Loop-carried mutable field state remains deliberately conservative. `examples/scalar_reference_object.ts` also keeps a selected string field live across sustained string-allocation GC pressure after the object has been scalar-elided. Physical stack placement has now started for non-scalarizable reference-bearing objects: non-aliased, non-escaping candidates receive dedicated GC shadow-root slots for every heap-reference field, `ObjectNew`/`FieldSet` keep those slots synchronized, and stack stores bypass the heap remembered-set barrier. Object aliases are still rejected conservatively until interior-pointer/provenance synchronization is explicit. `examples/stack_reference_object.ts` now forces the reference object to remain physical (`scalar=0`, `stack=1`) and, with a 1 KiB nursery plus sustained string churn, verifies the stack-held field survives repeated collections. Single-origin Phi aliases are now supported: codegen resolves them back to the unique physical stack object for barrier selection and field-root synchronization, while mixed/unknown aliases remain heap-backed. True interior-pointer/address-taking support remains pending because MIR does not yet expose such operations.

Every milestone must pass `go test ./...`, `go vet ./...`, native acceptance where applicable, and `git diff --check` before commit.
